# Project 4 — Code Generation (JVM Bytecode via Jasmin)

The fourth and final phase: the compiler now generates real, runnable JVM bytecode. It combines the Project 3 semantic analysis with a new code generator, producing Jasmin assembly that assembles into a working `.class` file.

## What this does

The full pipeline in `src/SimpleLang.java` is now:

```
parse → NameAnalyzer → TypeAnalyzer → print any errors
      → if no errors: CodeGenerator (emits Jasmin .j files)
```

A program with semantic errors produces the same diagnostics as Project 3 and no code. A valid program produces one `.j` file per module/struct.

- `src/main/ast/`, `src/main/symbolTable/` — the same AST and symbol table as Project 3 (unchanged).
- `src/main/visitor/`:
  - `NameAnalyzer`, `TypeAnalyzer`, `TypeUtils` — carried over from Project 3, with two small fixes discovered while integration-testing code generation (an unqualified constructor call like `BaseModule base = BaseModule();` is parsed as a `MethodCall`, not a `ConstructorCall`, due to grammar rule ordering — `NameAnalyzer` now recognizes this pattern for both declaration lookup and reachability analysis).
  - `CodeGenerator` — walks the AST and emits Jasmin assembly: one `.class` per module/struct (respecting `includes` for inheritance, topologically ordered), fields and methods with JVM-correct descriptors, constructors, and a generated `static main` wrapper for the entry class. It tracks local variable slots (`slotOf`), picks load/store/arithmetic/return instructions based on type (`int`/`bool`/`char` vs `float` vs `double` vs object references), and implements control flow (`if`/`while`/`for`/`break`/`continue`), short-circuit `and`/`or`, field access (`this.x`, `obj.x`), method dispatch, `output`/`input`, and correct stack ordering for field assignment.
- `Sample/` — reference files from the assignment (`BaseModule.j`, `Main.j`, `sample.mol`) plus `stress.mol`, an additional test program covering structs, inheritance, loops, `break`/`continue`, and all primitive types.
- `samples/Name/`, `samples/Type/` — the Project 3 semantic-analysis test cases, still passing (11/11) as a regression check.
- `run_phase2_tests.sh` — runs the Project 3 semantic-analysis test suite.
- `run_phase3.sh` — compiles the project, runs the compiler on a `.mol` file, assembles the output with `jasmin.jar`, and runs the resulting program.
- `REPORT_phase2.md`, `REPORT_phase3.md` — design write-ups (in Persian) for the semantic-analysis phase and the code-generation phase, including verified output (`sample.mol` → `20`/`20`, `stress.mol` output listed in the report) and edge cases handled (e.g. a method ending in a label with no trailing `return` needs one synthesized, or the JVM rejects it).

## Notes

The ANTLR-generated lexer/parser/visitor source files, `.class` files, and `codeGenOutput/` (generated `.j`/`.class` files) are not included since they're all regenerated by running the compiler. See `REPORT_phase3.md` for the full code-generation design.
